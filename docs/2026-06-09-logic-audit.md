# killallhumans — Full Logic Audit (2026-06-09)

**Scope:** entire repo at origin/main `291bd4b` (post PR #9 merge, iters 016–035 + competition interface).
**Method:** 9 parallel adversarial reviewers (estimation / planning-core / replanner-ILC-validator / control+flight_control / sequencer+race_pipeline / competition / sim_pybullet / detection+camera / benchmark+ML), each reading its modules completely and executing numerical repros in the repo venv where possible. Findings marked **[E]** were verified by execution, not just reading.
**Context:** full pytest suite is GREEN (427 passed, 1 skipped) — every finding below is latent under the passing suite.

---

## The five systemic failures

1. **Frame conventions are the #1 defect class.** "All pipeline modules use NED internally; the adapter layer converts" (CLAUDE.md) is violated at nearly every boundary, in both directions: the SE(3) tracker (3 separate bugs), pybullet_adapter (4), flight_control/adapter, racing-line up-vector, gate normals (3 modules agree with each other and disagree with the quaternion convention), plan_validator, EKF init. Two bug *pairs mutually cancel* (mirrored synthetic camera ↔ mirrored steering; ENU up-vector relabel masked by `max_vertical_offset=0`), which is how working demos and green tests coexisted with broken math.
2. **The benchmark optimized a lie.** All 43 logged `--mode full` runs in benchmark_history.jsonl have `simulation.skipped=true` AND `overall_passed=true`; tracking error is scored against the globally-nearest path point rather than the tracked reference; proximity-pass credits gates never crossed; the PyBullet bench replays the reference at 0.2× sim rate; the <30 s race threshold is enforced by nothing at defaults. The iteration loop's logged improvements need re-validation.
3. **The recovery stack cannot recover.** Crash → terminal hover *before* the replanner can see it; triggers arriving during the cooldown are consumed and never served; a replan that does fire runs 1.8 s of racing-line optimization synchronously inside the 100 Hz control callback AND re-initializes the EKF (yaw→0, biases wiped).
4. **Tests enshrine bugs.** `test_downward_error_increases_thrust` asserts the inverted-thrust behavior; the benchmark "honesty" adversarial assert is a tautology; the crash-replan integration test calls `_maybe_replan` directly — a path production can never reach; PnP tests synthesize pixels from the same object points and ordering they verify.
5. **AIGP contract gaps with no TODO anywhere:** no TIMESYNC sender exists; COLLISION messages never reach `sequencer.mark_collision`; the first-contact recorder never records vision and drops all fields of unmodeled message types; telemetry is wall-clock-stamped in a sim-time-authoritative design.

## BLOCKERS

### Control — the live competition attitude path (race_pipeline → mavlink send_attitude)
1. **[E] control/mpc_tracker.py:277-278 — GeometricTracker never rotates desired accel into the yaw frame.** Roll/pitch are extracted from *world*-frame thrust direction; the properly built body frame at :252-265 is computed then discarded. At yaw=90° a north error commands pure pitch (executed as east accel — 90° wrong); at yaw=180° acceleration is fully inverted → positive feedback, divergence. Survived because the bench consumes `last_desired_acceleration` and the PyBullet runner uses DSLPID — only the real competition path executes the broken code.
2. **[E] control/mpc_tracker.py:234-246 — Saturated descent flips the thrust vector.** Commanded downward accel > g (any target ≳1.2 m below, e.g. post-replan recovery) makes `thrust_vec` point down → drone banks 49° at 95% thrust and climbs sideways instead of descending. `test_tracker.py:157-168` asserts this as correct.
3. **[E] control/mpc_tracker.py:446-447 — SimplePositionTracker (the fallback tracker) uses ENU signs in the NED pipeline.** +x error → executed accel −0.75 g *away* from target; internally inconsistent (its thrust formula is NED-correct). Diverges immediately if `use_geometric_tracker=False`.

### Estimation — heading can't be acquired and gets lobotomized mid-race
4. **[E] estimation/ekf.py:189-254 — Orientation & gyro bias are structurally unobservable.** No update path touches ORI/GBIAS and F omits the cross-couplings, so their Kalman-gain rows are identically zero forever. Verified: 0.5 rad yaw error unchanged through 600 perfect odometry updates. Yaw initializes blind to 0 regardless of arm heading (race_pipeline.py:280) and race_pipeline.py:355 overwrites telemetry yaw with this dead value. In the PLAN 1.3 dead-reckon mode, position-only PnP fixes mathematically cannot repair heading → unbounded drift.
5. **race_pipeline.py:279-281 (via :511-515) — Every mid-race replan re-initializes the EKF.** `_build_trajectory_from` is shared by `configure()` and `_maybe_replan()` and unconditionally calls `ekf.initialize(..., timestamp_s=0.0)`: yaw→(0,0,0), biases wiped, covariance reset, clock rewound — at the exact moment the drone is recovering from a miss/crash. Independently found by 3 reviewers.
6. **[E] race_pipeline.py:206,596-600 — PnP drift correction self-disables beyond 3 m drift.** Fixes are accepted only within `_pnp_gate_match_radius_m=3.0` of the *current estimate*, and the best match is chosen by closeness to the prior (not reprojection quality) — circular validation: the drift corrector rejects corrections exactly when drift is large.

### Replan/recovery
7. **[E] planning/dynamic_replanner.py:163-201 — Consume-on-read triggers + cooldown permanently destroy events.** `evaluate()` moves new crash/miss IDs into seen-sets and latches level signals every tick; `should_replan()` gates on cooldown afterwards. Any edge landing in the 0.5 s cooldown is consumed and never served — reproduced 3 ways (new-gate crash at t=1.2 after t=1.0 replan → zero replans in 50 s; off-track entry during cooldown → RECOVERY forever). Same loss pattern at race_pipeline.py:515-520 (rebuild exception → trigger gone) and runner.py:963-964.
8. **race_pipeline.py:389-392 — Crash → terminal before the replanner can run.** `_control_callback` returns hover when `last_crash is not None`, and `session.should_stop` ends the run — both before `_maybe_replan` (:425). The gate_collision replan path (and PLAN Phase 2.2 "recover or safely continue") is unreachable dead code; `test_crash_triggers_trajectory_rebuild` passes only by calling `_maybe_replan` directly. One strut graze = race over.
9. **[E] race_pipeline.py:424-530 — Replan runs ~1.8 s of racing-line optimization synchronously in the 100 Hz control callback.** 13 candidates × full trajectory optimize + kinematic sim, inline; cache always misses mid-race (key includes start position). No attitude commands during rebuild = 14+ m blind at 8 m/s, triggered precisely when unstable.
