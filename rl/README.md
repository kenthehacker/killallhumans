# `rl/` — DCGame Composite Replica + Fidelity Gate (RL foundation)

This package is the **foundation** of the RL effort for AIGP drone racing: a
faithful, telemetry-fit **replica** of the official DCGame simulator's drone
response, plus a **fidelity gate** that measures whether the replica matches the
real sim. The gate decides whether RL trained on the replica can transfer.

**numpy / scipy ONLY** (CLAUDE.md mandate). No torch, no PyBullet in this package
— the replica is a lightweight gray-box numpy sim fit to real telemetry, which is
more faithful for *this* drone than PyBullet's generic quad physics. torch/PPO is
a later, separate dependency decision (Stage D).

---

## The critical reframe (why this is a *composite-map* replica, not physics)

We do **not** command or observe the drone's true rigid-body physics. We send
body-rate setpoints + a normalized thrust over MAVLink to DCGame's **closed-source
inner autopilot**, and observe the resulting state. Mass / inertia / motors / aero
are a black box and are **not separately identifiable**. What *is* observable — and
what RL actually consumes — is the **composite map**

```
(rate/attitude setpoint + thrust, current state)  ->  next state
```

So we system-ID and replicate **that map** from telemetry (`captures/rel_1..15`),
not first-principles dynamics.

## Files

| File | Role |
|---|---|
| `dcgame_replica.py` | The gray-box composite simulator (`DCGameReplica`, `ReplicaParams`, `ReplicaState`) + the attitude→body-rate wrapper (`attitude_to_body_rate`, byte-identical to the live `_attitude_error_body_rates`). |
| `fit_dynamics.py` | Fits the composite params from the captures; saves `dcgame_params.json`. |
| `champion_control.py` | Standalone, deterministic re-host of the **champion** control law (reuses `control.minimal_controller.MinimalController` + the pipeline's gate-by-gate aim/brake/slew), so the champion drives the replica unchanged. Read-only w.r.t. live code. |
| `validate_fidelity.py` | **THE GATE**: champion-in-replica vs ground truth + held-out open-loop prediction error + a clear verdict. |
| `dcgame_params.json` | The fitted params (regenerated by `fit_dynamics.py`). |
| `tests/` | Determinism, wrapper-equivalence, synthetic param recovery, validator-runs, the fidelity gate. |

Run:
```bash
python -m rl.fit_dynamics            # fit params -> rl/dcgame_params.json  (~70 s)
python -m rl.validate_fidelity       # the fidelity verdict
python -m pytest rl/tests/ -q        # tests (~17 s)
```

## Model structure

**Rotation (carries the bandwidth wall).** The achieved attitude tracks the
commanded attitude through a per-axis **first-order lag** (time constant `tau_i`,
DC gain `eff_i≈1`). The rate command is formed by the **exact champion PD law**
(`kp=(1,0.5,0.5)`, `kd=(0.4,0.2,0.2)`) and clamped to **±0.8 rad/s** — the real
signal chain. The achieved body rate is the achieved-attitude derivative. The
**0.53 roll attenuation** and the **~2 m/s descent wall** are *not hard-coded* —
they **emerge** from `tau_roll` + the rate clamp limiting how fast the bank /
thrust-vector can slew (verified in `validate_fidelity`).

**Translation (reused calibration).**
```
accel_NED = R(att) @ [0, 0, -thrust_norm * k_t] + g_NED - k_d * vel
```
`k_t = max_thrust/mass`, `k_d = drag/mass`, the same regression as
`competition/calibration.py` (extended to the full 3-D thrust vector). **DCGame
roll-sign convention** (`+roll → +Y` at yaw=π, telemetry-confirmed, opposite of
standard NED — the minimal controller carries the matching `roll=-roll`) is
reproduced so the replica is sign-consistent with the unmodified controller.

## Fitted params (from `captures/rel_1..15`, 15 clean champion runs)

| param | value | meaning |
|---|---|---|
| `k_t` | **33.9** | accel per unit normalized thrust (hover `g/k_t ≈ 0.29`, matches bench ~0.26–0.28) |
| `k_d` | **0.42** | drag per unit velocity (1/s) |
| `tau_roll` | **0.22 s** | roll inner-loop bandwidth (the slalom/attenuation axis) |
| `tau_pitch` | **0.10 s** | pitch inner-loop bandwidth |
| `tau_yaw` | **0.50 s** | yaw bandwidth (barely excited — held at π) |

**Data hazard handled:** the per-step `t_us` deltas in the captures are **corrupt**
(~half out of range, hundreds negative, median ~0.9 ms), but the *absolute* elapsed
time is clean (~10.2 ms/row). All fits and replays integrate at this **robust fixed
cadence**; using the per-step deltas inflates the open-loop error ~5×.

## Fidelity verdict (current)

**DYNAMICS GATE: PASS.** Champion-in-replica vs the ground truth:

| metric | replica | ground truth |
|---|---|---|
| course | 6/6 complete | 6/6 |
| lap g0→g5 | **16.85 s** | 16.2 s |
| per-leg splits (s) | 2.15 / 3.74 / 4.65 / 3.47 / 2.84 | 2.52 / 3.53 / 4.77 / 3.03 / 2.36 |
| descent g0→g3 | **2.33 m/s** | 2.27 m/s |
| 0.53 roll attenuation | **0.46** (emergent) | 0.53 |
| held-out open-loop pos RMS | **0.33 m @0.5s, 0.94 m @1s, 3.3 m @2s** | — |
| held-out open-loop att RMS | 0.20 rad @0.5–2s | — |

**Known fidelity gap (honest, RL-safe direction):** the replica's plane-crossing
miss is ~0.5–0.7 m larger than real on the **steep-descent slalom gates 2/3** (and
a launch-phase undershoot at g0), so the margin proxy flags those as breaches. The
replica is therefore *pessimistic* on the two hardest gates (it predicts a clip the
real drone clears) — the **safe** direction for RL (it cannot exploit margin that
isn't there). This is exactly the off-champion / aggressive-lateral regime where we
have the least excitation (see below).

## Is it faithful enough for transfer? Honest assessment

**Yes, for the champion regime** — and that is what gates the Stage-A/B work:
- The held-out 0.5 s position prediction (0.33 m) is small for a 15 m/s racer, and
  the closed-loop lap, per-leg splits, descent rate, and roll attenuation all match.
- The **bandwidth wall is reproduced** (the 0.53 attenuation and ~2 m/s descent
  wall emerge from `tau_roll` + the clamp). This is the load-bearing fidelity fact:
  RL on this replica will *also* hit the wall, so it won't learn a policy that
  relies on physics DCGame doesn't have.

**Where it is weakest (and why):**
1. **The aggressive / off-champion regime.** All 15 captures are the *same* champion
   lap, so the model is identified only on that narrow command distribution. The
   gates-2/3 lateral overshoot is the visible symptom: harder/faster slalom
   reversals than the champion ever flew are *extrapolation*. RL will push into
   exactly this regime, where the simple first-order-lag+clamp model is least
   trustworthy.
2. **`tau_roll` is only loosely identifiable open-loop** (the attenuation is a
   closed-loop effect), so it is pinned to the closed-loop-validated value; a wrong
   roll bandwidth is the most likely single-param error.
3. **`k_t` has a launch-phase cliff** (>34.5 the launch over-lifts). The point-thrust
   model absorbs the real airframe's lift/momentum-drag into thrust, so `k_t` is the
   closed-loop-consistent value, not a clean physical one.
4. **No quiescent/hover or high-rate excitation** in the data (the champion never
   hovers level), so `k_t`/`k_d` rest entirely on the dynamic regression.

**Bottom line:** trustworthy as a *champion-regime* training/eval sim and a wall-
faithful floor; treat any RL policy that wins by flying *more aggressively than the
champion at gates 2/3* with suspicion until validated on the real sim (Stage E).

## What telemetry/excitation is missing (to harden the off-champion regime)

To make the replica trustworthy where RL will actually explore, collect telemetry
that **excites the map off the champion trajectory** (all need the live DCGame sim):

- **Roll/pitch frequency sweeps (chirps) at several amplitudes**, especially fast
  large-amplitude roll reversals (>0.5 rad at >1 Hz) — directly identifies
  `tau_roll` and whether a single first-order lag suffices or a 2nd-order /
  rate-dependent model is needed near the clamp.
- **Thrust steps + a hover hold** (level, low vertical rate) — pins `k_t`/`k_d`
  cleanly and removes the launch-cliff ambiguity; a few seconds of genuine hover
  would resolve the 33–38 `k_t` band the dynamic-only fit leaves open.
- **Steep-descent sweeps at varied descent rates** (push past ~2 m/s to the
  tumble) — characterises the descent wall as a function of bank/thrust-vector
  slew, the exact gates-2/3 weakness.
- **Off-axis / coupled maneuvers** (simultaneous roll+pitch+yaw) — checks the
  per-axis-independent lag assumption.
- **Fix the telemetry timestamping** (or log a monotonic loop counter) so per-step
  `dt` is usable and the fits don't depend on the robust-cadence workaround.

Stage E's residual learner (below) is the pragmatic complement: it corrects the
champion-regime model from a little real rollout data without re-deriving physics.

## Staged RL plan

- **Stage A — Replica** *(DONE)*: `dcgame_replica.py`, fit to telemetry.
- **Stage B — Fidelity gate** *(DONE / PASS for the champion regime)*:
  `validate_fidelity.py`. Stage B is the gate for the whole effort; it passes on
  the dynamics (lap, splits, descent, attenuation, held-out prediction), with a
  documented, RL-safe pessimistic gap on gates 2/3.
- **Stage C — Gym env + reward**: wrap `DCGameReplica` in a gym-style
  `step/reset` env. State = (pos, vel, att, rate, next-gate relative); action =
  body-rate setpoint + thrust (the native composite-map input). Reward =
  gate-progress (distance-to-next-gate decrease) + gate-pass bonus + crash/breach
  penalty + a time penalty; terminate on completion / breach / out-of-box. Keep
  numpy-only.
- **Stage D — PPO training**: *separate dependency decision* (torch). Train PPO on
  the Stage-C env. **Strategic caveat: a faithful replica imports the bandwidth
  wall**, so RL is likely floored near ~16.2 s **unless** the remaining headroom is
  control-suboptimality (e.g. better lateral tracking at gates 2/3, smoother speed
  scheduling) rather than physics. Frame the RL objective accordingly — chase the
  *control* gap, not a physics gap that doesn't exist.
- **Stage E — sim→DCGame residual fine-tuning** (Swift recipe): after a policy is
  trained, close the sim-to-real gap with a **KNN residual** model (k=5) learned
  from ~50 s of real DCGame rollouts: predict the replica's per-step state-error and
  add it back during rollout / fine-tuning. This is the cheap, data-efficient fix
  for exactly the off-champion regime the replica is weakest in, and it does not
  require re-identifying physics.
